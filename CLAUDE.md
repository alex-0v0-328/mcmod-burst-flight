## Project

- Burst Flight, mod id `burst_flight` (Alex, 2026-10-02), package `net.alex.burstflight`: double-tapping the sprint key starts creative-style flight at a multiple of vanilla creative flight, default 3x; double-tapping again or touching the ground ends it. That is the whole mod (Alex: one feature only), plus one option he added the same day: the view widens during a burst (client config `fovEffect`, `fovIncrease`). The in-game config screen (mod list → Config) is NeoForge's generated one, labeled in `en_us.json` only; no other language gets labels (Alex, 2026-10-02). Each option names its key with `.translation`, `burst_flight.config.<option>` plus `.tooltip` (Alex, 2026-10-03); the screen title and section buttons keep NeoForge's own English, since their keys are fixed under `burst_flight.configuration.`. `README.md` (Simplified Chinese) is the source README, `README.zh-TW.md` (Traditional Chinese) and `README.en.md` are its translations: change them to follow the Simplified Chinese, never the reverse.
- Two audiences (Alex, 2026-10-02): the GZR modpack, where it is one mod in `../guzhenren/run/mods`, and other modders, who use it standalone or depend on it. Hence MIT, a public repository and JitPack: `com.github.alex-0v0-328:mcmod-burst-flight:<tag or commit>`, built by JitPack from `jitpack.yml` (Java 21) with `build publishToMavenLocal`. The published artifact carries a sources jar.
- Minecraft 1.21.1 on NeoForge through ModDevGradle, Java 21, no other dependency. Versions live in `gradle.properties` only. `neo_version` is pinned to the GZR dev client's (`../guzhenren/gradle.properties`), so the compiler proves no newer API is used; the `neoforge.mods.toml` range stays open-ended. When the GZR pin moves, ask Alex before moving this one.
- Both sides are required: the client detects the double tap and scales its own flight, the server decides and grants. The two payloads are required channels, so a client or server without the mod cannot join the other.
- Who may fly (Alex, 2026-10-02): everyone by default, through the server config (`multiplier`, `everyone`); other mods override per player through `api/BFApi` (`allow`, `allow` with a multiple, `deny`, `reset`; renamed from `BurstFlightApi` by Alex on 2026-10-03, before any release tag). The API is the compatibility contract: keep its names and semantics, and record any change in the READMEs.
- Code structure (Alex, 2026-10-03; the pilot for GZR's package decision D1, high cohesion and low coupling): one package per feature, `permission`, `session`, `client.input`, `client.speed`, `client.view`, with `api` as the facade. Dependencies point one way, `client` → `session` → `permission`, `api` → `session` and `permission`; nothing outside `client` names client code, so the server-to-client payload reaches the client through the `SessionPayloads#setStateHandler` hook its entry point sets. Every package may use `BurstFlight.MOD_ID`. Names: the `BF` prefix only on classes other mods or the loader see (`BFApi`, `BFClientMod`; the common entry keeps the mod's name, `BurstFlight`); internal classes take plain names their package explains (`ServerConfig`, `ClientConfig`, `SessionController`). Mixins live in their own `mixin` subpackage of the feature they serve.
- Mechanics that must hold: flight comes from a transient modifier on NeoForge's `creative_flight` attribute, never from `Abilities#mayfly`; the speed is never written to `Abilities` (only `LocalPlayerMixin` scales the local player's flight), so nothing scaled reaches a save; multiples are clamped to 1..8, because above about 9.9 a sprinting burst trips the vanilla server's "moved too quickly" check. At 3x a sprinting burst covers about 60 blocks a second, close to an elytra dive (about 3.75 chunks a second of new terrain).

## Language and style

- Chat in Chinese (zh-CN); code, comments and commit messages in American English; this file in English.
- The GZR code conventions apply here, as in Camera Shift. `.editorconfig`, a copy of GZR's, keeps the automatable part; the rest, condensed from GZR reference《写作与命名》:
  - Comments live only in the top-level class Javadoc: no `//` in method bodies and no Javadoc on fields, methods, constructors or nested types; the class Javadoc points at a member with `{@link #member}`. Only `//region` labels and TODO anchors stay in place, and a `//region` label must match its code. Explain non-obvious reasons, contracts and limits; never restate the code. The Javadoc ends with `@author Alex`, `@version 1.0.0`, optional `@see`, `@since 1.0.0`. Cross-package Javadoc references use the fully qualified name.
  - Blank lines: one after a type's opening brace, none before its closing brace, none at the top of a method or block body; exactly one between members, placed above Javadoc and annotations; consecutive fields form one block with no blank lines; one between the top-level class Javadoc and the declaration; at most one between logical steps inside a method.
  - Braces: an empty body is `{}` on one line (`private X() {}`); a one-line brace pair with content keeps a space inside (`{ return x; }`).
  - Imports form one block in plain ASCII order, static imports in their own block first, no wildcards. Constants are `UPPER_SNAKE` (`MOD_ID`). Clamping uses `Math.clamp`. No hand-aligned argument columns; lines stay within 120 characters.
- Naming, shared by the three mods (Alex, 2026-10-03):
  1. Parameters and locals are whole words: `player` (a `ServerPlayer` too), `stack`, `level`, `entity`, `event`, `value`, `delta`, `amount`, `index`, `ticks`. `x`, `y`, `z` and `id` count as whole words, and idiomatic factory short names (`id`, `instance`, `source`, `key`) stay. Only loop indices take `i`, `j`.
  2. One concept, one name across the repository; two concepts never share one.
  3. Methods start with a verb: `get`/`is`/`has` read, `set`/`add`/`shift` write, `tick` advances one tick, `refresh` recomputes derived state, `on` handles an event.
  4. A class name does not repeat what its package already says; only entry classes other mods or the loader see carry the mod prefix.
  5. One class, one job: a class over 300 lines or a method over 40 is split or states why; package dependencies point one way, with no cycles.
- New code matches its neighbors' comment density, naming and idiom. Markdown tables stay aligned: after touching one, `python ../guzhenren/tools/md_tables.py <file>` must report nothing.
